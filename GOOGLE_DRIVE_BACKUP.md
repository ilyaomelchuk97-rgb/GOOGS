# Автоматические копии Forma на ваш Google Диск

**Что получится:** сайт **проверяется каждый час с 08 до 17 включительно по Минску**, каждый день. Если рабочие данные **отличаются от последней успешно сохранённой копии**, появляется ZIP, например `Forma_2026-10-06_08-23-14_Minsk.zip`; если изменений нет — новый файл **не создаётся**. Все старые копии **сохраняются** — скрипт ничего не удаляет. Google Apps Script выбирает минуту запуска сам; это не гарантия проверки ровно в `:00` или без пропусков при сбоях сервисов.

**Перед началом:** сайт уже должен быть запущен на Render с D1, вход и ручное скачивание ZIP-копии в админке должны работать. Код для автоматизации находится в `google_drive_backup.gs`. Ваши Google, Render и Cloudflare аккаунты этой инструкцией не подключаются автоматически.

## Шаг 1. Секрет только для резервных копий

Откройте свой менеджер паролей (или встроенный генератор паролей браузера) и создайте **новый случайный пароль длиной не меньше 40 символов**. Сохраните его там: это отдельный секрет для бэкапов. Никакого терминала или программирования на вашем компьютере не требуется. **Не отправляйте её в чат и не записывайте в GitHub.** Это отдельный ключ: он не даёт войти в админку, только скачать ZIP с личными данными. Если его украдут, копии смогут скачать посторонние — замените ключ с обеих сторон.

## Шаг 2. Render

В панели вашего **Web Service → Environment** добавьте:

- **Key:** `AUTOMATED_BACKUP_TOKEN`
- **Value:** случайная строка из шага 1.

Сохраните настройку и дождитесь успешного перезапуска/деплоя Render. Не используйте вместо неё администраторский пароль или `D1_API_KEY`. Новый закрытый маршрут сайта `/internal/backup` принимает только **POST** с этим ключом; без него возвращает 403. Открывать адрес в браузере бесполезно: обычный GET не выдаёт файл.

## Шаг 3. Google Диск — одноразовая настройка

1. Под своим Google-аккаунтом откройте <https://script.google.com/> → **Новый проект**. Назовите его, например, «Forma Backup». **Не делайте проект общедоступным и не предоставляйте чужим людям право редактирования**.
2. Удалите пример кода из `Code.gs`, вставьте **целиком** содержимое файла `google_drive_backup.gs` из архива кода и сохраните. В самом коде секретов быть не должно.
3. Слева откройте **Настройки проекта** (значок шестерёнки) → **Свойства скрипта** → **Добавить свойство**. Добавьте два свойства:
   - `FORMA_URL` → `https://ВАШ-САЙТ.onrender.com` (**без** `/health`, `/internal/backup` и завершающего `/`);
   - `BACKUP_TOKEN` → тот же секрет из шага 1.
4. В редакторе выберите функцию **`setup`** и нажмите **Запустить**. Google попросит один раз разрешить доступ к Google Диску и внешним HTTP-запросам — проверьте, что это ваш проект, и подтвердите. Скрипт создаст **отдельную папку «Forma — резервные копии»** на вашем Диске, сохранит её ID в свойствах и установит **один** почасовой триггер. Повторный запуск `setup` не размножает триггеры.
5. Для немедленной проверки выберите функцию **`testBackupNow`** и нажмите **Запустить**. Она проверяет данные **даже вне расписания**. При первом запуске должен появиться ZIP `Forma_ДАТА_ВРЕМЯ_Minsk.zip`; если копия уже есть и ничего не менялось, нового файла не будет. Убедитесь, что ZIP открывается и соответствует нынешнему количеству записей, затем сохраните дополнительную копию на свой компьютер.
6. Проверьте **Триггеры** (значок часов): там должен быть один триггер функции `runBackup`, запускаемый «каждый час». В **Выполнениях** можно смотреть успешные/неуспешные запуски. Периодически проверяйте содержимое папки: ни Render Free, ни Google Apps Script не дают гарантии бесперебойной работы.

Если хотите выбрать уже существующую **закрытую** папку вместо автоматического создания, до запуска `setup` добавьте третье свойство `FOLDER_ID` со значением ID папки из адресной строки Google Диска. **Никому не открывайте общий доступ к папке:** ZIP содержит сведения о сотрудниках и хеши паролей.

## Важно

- **Что считается изменением:** учётные записи и права (включая пароль), каталог работ, выполненные работы, комментарии, посещаемость, настройки часов и **новые сообщения чата**. Вход/выход пользователя, отметка «в сети», розыгрыши и записи только в журнале действий не создают лишний ZIP. Сам журнал входит в следующую копию, которая будет сделана при изменении рабочих данных. Проверка сравнивает текущее содержимое с **последней действительно сохранённой копией**; после сетевой ошибки отметка не обновляется, чтобы попробовать снова в следующий час. Если последняя сохранённая копия удалена с Диска, скрипт создаст новую.
- Время учитывается по `Europe/Minsk`; в текущем варианте 08–17 — **включая 17-й час и выходные**. Имя ZIP содержит фактическое время создания. Часовой триггер Google может сработать не ровно в начале часа; повтор в одном и том же часу скрипт пропускает.
- Если Render спит, пробуждается слишком долго, Cloudflare/Google недоступны или закончились квоты, копия за этот час может не появиться. Просматривайте ошибки в **Apps Script → Выполнения** и не храните единственную копию только там.
- Сайт отдаёт тот же совместимый ZIP, что скачивается из админки: его можно проверить и восстановить через «Резервные копии» с обычным сравнением данных перед заменой. Бэкап на Диске не заменяет независимую локальную копию.
- Google Apps Script и Drive имеют ограничения по времени выполнения и размеру ответа; для большой выросшей базы схема потребует доработки. Сейчас архив базы порядка десятков килобайт.
- Случайный ключ и `BACKUP_TOKEN` — **секреты**, не присылайте их мне и не помещайте в исходный код. При замене ключа сперва обновите Render, затем свойство скрипта и проверьте `testBackupNow`.

Документация Google: [часовые триггеры](https://developers.google.com/apps-script/reference/script/clock-trigger-builder), [лимиты Apps Script](https://developers.google.com/apps-script/guides/services/quotas).
