# Forma: технические заметки к публикации

Пошаговая инструкция для владельца: **[DEPLOY_SIMPLE.md](DEPLOY_SIMPLE.md)**. Этот файл — дополнительные сведения для разработчика.

## Архитектура

- Python stdlib HTTP-сервер на Render: `python app.py`, `DATABASE_BACKEND=d1`.
- `d1_store.py` делает серверные HTTPS-запросы к защищённому Cloudflare Worker; браузер никогда не получает `D1_API_KEY`. Worker проверяет `X-Forma-Bridge` против Cloudflare-секрета `BRIDGE_TOKEN` и обращается к связанному D1.
- `cloudflare/wrangler.jsonc`: замените фиктивный `database_id` на реальный. Примените `cloudflare/schema.sql` к **remote** D1 до переноса. `cloudflare/src/index.js`: `/v1/query` и транзакционный `/v1/batch` (максимум 40 инструкций, предел тела 512 КБ). Не публикуйте эти эндпоинты без длинного секрета.
- Перенос из проверенного администрацией SQLite ZIP в пустую D1: `migrate_to_d1.py --archive private-backup.zip [--apply]`. Сверяются количества и отпечаток бизнес-данных. Повторный перенос в непустую базу запрещён. Не переносите при работающем старом сайте/другом писателе в D1.
- Админский ZIP сохраняет прежний SQLite-формат; перед скачиванием данные D1 выгружаются во временную SQLite в памяти. Restore после сравнения и проверки отпечатка выполняется единым D1 batch: либо все таблицы меняются, либо ничего. Сеансы/временные события сбрасываются. Текущий предел: 490 КБ несжатого JSON-пакета, 40 SQL-инструкций; при превышении восстановление прерывается **до записи**. Для большей базы нужен новый механизм восстановления, а не разбиение на неатомарные пачки.
- Перед restore создаётся ZIP на диске сервиса и доступен через админку, но **Render Free не обеспечивает сохранность этого файла** после рестарта/деплоя. Пользователю необходимо хранить скачанные копии вне Render.
- `GET /health`: ответ процесса без запроса к D1. Cron Worker раз в 10 минут обращается к HTTPS `RENDER_HEALTH_URL` с путём `/health` на `*.onrender.com`; вызовы не гарантируют бессонную или бесперебойную работу Render Free.
- Для Google Диска есть отдельный **только читающий бэкап** `POST /internal/backup`, доступный лишь с длинным секретом в заголовке `X-Forma-Backup-Key` (`AUTOMATED_BACKUP_TOKEN` в Render, `BACKUP_TOKEN` в свойствах Google Apps Script). Дополнительный `X-Forma-If-Unchanged` сравнивается с отпечатком рабочих таблиц; при отсутствии изменений сервер отвечает HTTP 204 без ZIP и без смены отметки о последнем сохранённом файле. Журнал входов/выходов и временные статусы не запускают создание копии; архив при следующем реальном изменении всё равно содержит журнал. Никогда не используйте администраторский пароль или секрет D1 в Google. `google_drive_backup.gs` запускается примерно раз в час и сохраняет совместимый ZIP в папку владельца **только при изменении данных**: см. [GOOGLE_DRIVE_BACKUP.md](GOOGLE_DRIVE_BACKUP.md). Реальная интеграция с аккаунтом Google остаётся ручной до его авторизации.

## Ограничения и эксплуатация

- Render должен работать в одной инстанции: `DB_LOCK` локален одному Python-процессу. Для масштабирования на несколько инстанций необходима распределённая координация транзакций, резервных копий и восстановления.
- Worker держит SQL-доступ к D1 за shared secret; утечка ключа равна утечке данных. Сгенерируйте случайный секрет, храните только в Cloudflare Secrets и Render Environment; при утечке замените в обоих местах. В логах никогда не пишите значения заголовка или пароли.
- Ограничение скорости/квот Cloudflare может остановить запросы до сброса суточного лимита; высокочастотный трафик Render Free к внешней базе также может привести к приостановке бесплатного сервиса.
- Отказ сетевого вызова после отправки записи имеет неизвестный результат: перед повторной отправкой проверьте состояние, не рассчитывайте на «ровно один раз». Большинство связанных изменений группируются в один D1 batch, но создание сотрудника/работы сначала сохраняет запись отдельно для получения нового `id`, а журнал действий — следующим запросом; если второй запрос упадёт, запись может существовать без записи в журнале. Для строгой атомарности этих двух операций нужен отдельный серверный SQL-сценарий.
- Admin `admin` в исходном архиве — демонстрационный пароль, измените его в D1 локально до публикации Render; не выставляйте архив и секреты в GitHub.
- `test_app.py` проверяет SQLite на отдельной копии; D1-эндпоинты, перенос, резервная копия/восстановление, смена логина и прав проверены с локальным `wrangler dev` и локальной D1. Реальную Cloudflare/Render публикацию необходимо проверять после настройки аккаунтов.
