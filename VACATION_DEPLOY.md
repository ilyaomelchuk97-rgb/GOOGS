# Раздел «Отпуск»: установка и перенос исходной таблицы

## Что будет на сайте

После установки в боковом меню появится пункт **«Отпуск»**. Его видят сотрудники и администраторы. Год листается стрелками. Верхняя таблица — ФИО из карточек сайта, 12 месяцев, даты отпусков (начало и окончание) и автоматически подсчитанные календарные дни. Нижняя повторяет ФИО и месяцы: «+» возникает вместе с датами; администратор нажимает на него и подтверждает **«Добавить материальную помощь»** — будет зелёная ячейка **«+М»**. При удалении дат исчезает и нижняя отметка. Только администратор может сохранять даты, удалять периоды, переключать материальную помощь и загружать файл. Сотрудники смотрят и могут распечатать или выгрузить таблицу, но не меняют её.

**Печать** справа вверху открывает окно над страницей с двумя кнопками: **«Печать»** (диалог печати браузера, обе таблицы) и **«Вывод в эксель»** (скачивание отдельного XLSX за выбранный год).

## Опубликовать обновление (без терминала)

1. Сохраните **личную ZIP-копию действующей базы** через раздел «Резервные копии». Не публикуйте её в GitHub.
2. Скачайте `forma-code-for-github.zip` из ответа и распакуйте. В репозитории https://github.com/ilyaomelchuk97-rgb/GOOGS откройте основную ветку **main**.
3. В корне репозитория через **Add file → Upload files** загрузите из архива `app.py`, **`vacation.py`**, **`sotipb.py`**, `backup_tools.py`, `d1_store.py`; подтвердите **Commit changes**. Новый файл обязателен: без него сайт не запустится.
4. В папке `web/` через **Add file → Upload files** замените `main.js`, `styles.css`, `index.html`. Сохраняйте остальные картинки (`effect-*.png`, `chat-*.png`, официальный знак, кот) в `web/`. Если каких-то картинок в GitHub ещё нет, загрузите их туда из архива.
5. В папке `cloudflare/` обновите `schema.sql` из архива для новых установок. **Не создавайте новую D1 и не меняйте Worker или секреты**. На работающей D1 новую таблицу создаст `app.py` при запуске.
6. Дождитесь **Render → Events / Deploys → Live**. В `https://googs-seogs.onrender.com/health` должна отображаться версия **`20261020-44`**. Старый номер означает, что обновление ещё не установлено. Перезагрузите страницу с **Ctrl+F5**. Войдите администратором и проверьте пункт «Отпуск».

## Перенести именно присланный XLSX, не раскрывая личные данные в GitHub

Файл с ФИО и датами **не включён** в публичный ZIP кода. Скачайте его отдельно из ответа (`vacation-source.xlsx`) себе на компьютер.

1. В разделе **«Отпуск»** выберите **2027 год**. В исходной книге заголовок «2026», но реальные даты в ячейках — **2027**; по вашему выбору переносим их к 2027 году.
2. Нажмите **«Загрузить исходный XLSX»** и выберите файл. Появится предварительная сверка: сколько ячеек будет добавлено, сколько уже заполнено и таблица соответствий исходных ФИО сотрудникам сайта. Если совпадение неверно или человека не нашли, выберите нужного сотрудника из списка вручную либо пропустите строку. **Предпросмотр ничего не меняет.** Сопоставление работает по фамилии, если она однозначна, или по полному ФИО.
3. В исходной книге есть **Бутько Владислав Сергеевич**, а в карточках сотрудников текущей копии сайта Бутько нет. Если он должен быть в плане, сначала добавьте его как сотрудника в разделе **«Сотрудники»** с персональным логином и паролем. Затем вернитесь в «Отпуск» и повторите загрузку. Никаких аккаунтов импорт не создаёт.
4. Проверив список, нажмите **«Импортировать … новых ячеек»**. Если другой администратор успел поменять план после предпросмотра, импорт остановится и попросит обновить предпросмотр. Уже существующие на сайте даты и «+М» импорт **не перезапишет**. Можно повторить импорт после добавления недостающего сотрудника. Лишние «+» без даты в верхней таблице не переносятся: в новой странице нижние плюсы всегда следуют за датами.
5. Проверьте несколько сотрудников и месяцев, затем откройте «Печать» и испытайте оба способа вывода. Скачайте свежую личную ZIP-копию базы: раздел «Отпуск» в неё теперь входит. Часовая проверка Google Диска считает изменения в отпусках содержательными.

**Важное ограничение:** один период отпуска на одного сотрудника в месяц начала отпуска, как одна ячейка в присланной таблице. Продолжение периода может выходить за пределы месяца. Количество дней считается по календарю включительно; правовые правила подсчёта и праздники автоматически не применяются.
