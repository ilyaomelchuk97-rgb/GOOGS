# Forma: публикация без терминала — только браузер, файлы и кнопки

**Это новая инструкция вместо старой инструкции с командами.** Вам **не нужны** командная строка, Node.js, Python на своём компьютере, Wrangler или ручной ввод SQL. Код сайта вы **перетащите в GitHub**, личную ZIP-копию данных **перетащите на защищённую страницу сайта**. Для Cloudflare Worker есть **одно исключение**: прямой загрузки нашего Worker перетаскиванием в нужный редактор нет; вы выбрали открыть `cloudflare/src/index.js`, **скопировать весь текст и вставить** его в редактор Cloudflare. Настройки и секреты вводятся в поля сайтов.

**Важно:** ни GitHub, ни Cloudflare, ни Render, ни ваш Google Диск пока не подключены к этой рабочей среде. Шаги ниже должны быть выполнены в ваших аккаунтах. Если название кнопки немного отличается, ищите указанное рядом слово; не перетаскивайте файлы в незнакомый сервис наугад.

## Перед началом: скачайте ДВА разных архива

1. **Код без личных данных:** скачайте `forma-code-for-github.zip` и распакуйте на компьютере. В нём лежат `app.py`, папки `web/` и `cloudflare/` и эта инструкция. Для GitHub нужны **распакованные файлы**, а не сам ZIP.
2. **Личная копия данных:** скачайте отдельно `backups/forma-private-backup-20261006-083833.zip`. В ней были **11 пользователей и 2203 записи**. Если после её создания сотрудники добавляли новые данные в старом сайте, войдите туда администратором → **Резервные копии → Скачать** и используйте **самый свежий** ZIP. Этот ZIP содержит данные и хеши паролей. **Никогда не загружайте его в GitHub или Cloudflare и не отправляйте в чат.** Храните отдельно. Перед переносом попросите сотрудников прекратить работу в старом сайте: иначе их новые записи останутся там, а не в D1.
3. В своём **менеджере паролей** создайте **два разных** случайных секрета длиной **не меньше 40 символов**. Назовите их у себя «Ключ D1» и «Ключ разовой загрузки». Не используйте пароль `admin`, не вписывайте секреты в файлы кода и не присылайте их сюда. Первый будет одинаковым у Cloudflare и Render; второй — только у Render и на странице переноса.

## Шаг 1. GitHub: перетащить код

1. Откройте <https://github.com/> и войдите в свой аккаунт. Создайте новый репозиторий: **New repository** → имя, например `forma-site` → **Private** → **Create repository**. Галочку «Add a README» можно не ставить.
2. Откройте **распакованную** папку `forma-code-for-github` на компьютере. На странице нового репозитория GitHub выберите **Add file → Upload files** (в пустом репозитории — ссылку **uploading an existing file**). **Перетащите содержимое папки**, включая папки `web` и `cloudflare`, в окно браузера. Нажмите **Commit changes**.
3. Проверьте в GitHub: на верхнем уровне видны `app.py`, `requirements.txt`, папка `web`; в `web` есть `index.html`, `styles.css`, `main.js`, `setup.html`; в `cloudflare/src` есть `index.js`, а в `cloudflare` есть `schema.sql`.
4. **Стоп-проверка:** в GitHub **НЕ** должно быть `worktrack.sqlite3`, `source.xlsx`, `initial_credentials.txt`, личного ZIP, папки `backups`, файлов `.env` или текста ваших секретов. Если случайно загрузили личные данные — не продолжайте настройку, сначала удалите репозиторий и попросите помощи: удаление одного файла из последнего изменения не удаляет его из истории Git.

## Шаг 2. Cloudflare: создать пустую базу D1

1. Откройте <https://dash.cloudflare.com/> и войдите. Найдите раздел **D1 SQL Database** / **D1** (он может находиться в «Storage & databases»).
2. Нажмите **Create database**, назовите её `forma-db` и подтвердите. **Не загружайте сюда ZIP с данными и не вставляйте SQL из `schema.sql`.** Пустые таблицы создаст Forma при первом старте. Базу не удаляйте после переноса.

## Шаг 3. Cloudflare: создать Worker и вручную вставить один файл

1. В Cloudflare откройте **Workers & Pages → Create application → Start with Hello World! / Get started**. Назовите Worker `forma-d1-bridge` и нажмите **Deploy**. Это пока временный шаблон, не наш сайт. Вам покажут адрес вида `https://forma-d1-bridge.ВАШ-АККАУНТ.workers.dev`; сохраните его.
2. Откройте этот Worker → **Bindings → Add binding → D1 database**. В поле **Variable name** напишите **ровно `DB`** (две заглавные латинские буквы), выберите базу `forma-db`, нажмите **Add binding** и сохраните/разверните изменение. Другое имя здесь не сработает.
3. В Worker откройте **Settings → Variables and Secrets → Add**. Тип — **Secret**, имя — **`BRIDGE_TOKEN`**, значение — ваш «Ключ D1» из менеджера паролей. Нажмите **Deploy/Save**. **Не** выбирайте публичную переменную вместо Secret.
4. На компьютере откройте **текстовым редактором** файл `cloudflare/src/index.js` из распакованного архива. Выделите всё (`Ctrl+A`) и скопируйте (`Ctrl+C`). В Cloudflare у Worker нажмите **Edit code**, выделите весь код шаблона, вставьте наш (`Ctrl+V`), нажмите **Save / Deploy**. Это **единственная вставка кода в Cloudflare**, которую вы заранее разрешили; остальные файлы туда перетаскивать не нужно.
5. Проверьте, что у Worker всё ещё есть привязка **D1 `DB`** и секрет **`BRIDGE_TOKEN`**. Не путайте **Cloudflare Pages → Drag and drop** с Worker: Pages предназначены для другого способа публикации и не заменяют этот приватный мост.

## Шаг 4. Render: включить сайт с временной страницей переноса

1. Откройте <https://dashboard.render.com/> → **New → Web Service**. Разрешите Render доступ к **приватному** репозиторию GitHub `forma-site` и выберите его.
2. Выберите план **Free**. Если панель просит команды запуска, **вставьте только в соответствующие поля Render** (ничего на своём компьютере запускать не нужно):
   - **Build Command:** `pip install -r requirements.txt`
   - **Start Command:** `python app.py`
3. **До нажатия Deploy** добавьте в Render → **Environment** ровно четыре записи:
   - имя `DATABASE_BACKEND` → значение `d1`;
   - имя `D1_WORKER_URL` → полный HTTPS-адрес Worker из шага 3 **без** `/v1/query` и без последнего `/`;
   - имя `D1_API_KEY` → **тот же** «Ключ D1», что вы вписали как `BRIDGE_TOKEN` в Cloudflare;
   - имя `INITIAL_IMPORT_TOKEN` → ваш **другой**, «Ключ разовой загрузки».
4. Нажмите **Create Web Service / Deploy**. Дождитесь статуса **Live**. Если сайт не стартует, смотрите **Logs**: частые причины — ошибочно написанное имя переменной, разные «Ключи D1» или отсутствие привязки `DB` у Worker. **Не** переключайте Render на SQLite ради обхода ошибки: её локальные данные на бесплатном плане пропадут.
5. Откройте `https://ВАШ-САЙТ.onrender.com/health`. В ответе должны быть `"ok": true` и `"backend": "d1"`. Затем откройте **`https://ВАШ-САЙТ.onrender.com/setup`**. Это одноразовая страница загрузки. Пока D1 пуста, обычный логин ещё не работает — это ожидаемо.

## Шаг 5. Перетащить личный ZIP на страницу Forma

1. На странице `/setup` перетащите **личный архив из «Перед началом», пункт 2**. **Не** перетаскивайте туда `forma-code-for-github.zip`.
2. Введите «Ключ разовой загрузки» из Render (`INITIAL_IMPORT_TOKEN`). Придумайте **новый пароль главного администратора**: минимум 14 латинских символов/цифр/знаков без пробелов. Повторите пароль и сохраните его в своём менеджере паролей.
3. Нажмите **Проверить и перенести данные** и дождитесь ответа. Forma проверит архив, перенесёт данные одной транзакцией в пустую D1, сверит записи и **заменит старый пароль администратора на новый до первого публичного входа**. При старой копии ориентир: **11 пользователей, 2203 записи**; для более свежей копии числа могут быть больше.
4. Если связь оборвалась, **не загружайте ZIP второй раз наугад**. Сначала проверьте главную страницу и новый пароль: если вход работает, перенос уже произошёл. Если `/setup` сообщает, что база непуста, повтор запрещён для защиты ваших данных.
5. После успешной загрузки вернитесь в **Render → Environment** и **удалите `INITIAL_IMPORT_TOKEN`**, сохранив настройки. Зайдите на главную страницу Forma под логином, который показала страница переноса (обычно `admin`), и **новым** паролем. В панели администратора откройте **Резервные копии → Скачать** и сохраните новый ZIP отдельно: старый ZIP всё ещё содержит **старый** пароль. Сверьте отчёт, сотрудника, даты и количества.

**Предел:** текущий способ однократного переноса принимает ZIP до 25 МБ, но транзакция D1 рассчитана примерно на **490 КБ несжатого пакета данных**. Ваша проверенная копия с 2203 записями помещается. Если данных стало намного больше и форма выдаст ошибку размера, не делите архив вручную: нужна отдельная безопасная схема переноса.

## Шаг 6. Cloudflare: включить проверку Render каждые 10 минут

1. Теперь, когда у сайта появился адрес, вернитесь к Worker в Cloudflare → **Settings → Variables and Secrets → Add → Secret**. Имя **`RENDER_HEALTH_URL`**, значение — **полный** адрес `https://ВАШ-САЙТ.onrender.com/health`. Сохраните и подтвердите **Deploy**.
2. В том же Worker откройте **Settings → Triggers → Cron Triggers → Add** (названия панелей могут слегка меняться). В поле расписания впишите **`*/10 * * * *`**, сохраните. Это **настройка расписания в веб-панели**, не команда для терминала. Проверьте появление расписания в списке триггеров.
3. Тик может уменьшить засыпание Render Free, но **не гарантирует** бесперебойную работу или бесплатность без ограничений. Он не заменяет регулярное скачивание резервных копий.

## Шаг 7. По желанию — копии на Google Диск

Есть отдельная [инструкция для Google Диска](GOOGLE_DRIVE_BACKUP.md): проверять изменения в часах **08–17 по Минску** и сохранять ZIP только если рабочие данные изменились. Она тоже обходится **без терминала**, но Google Apps Script, как и Worker, требует **вставить текст одного файла в веб-редактор** и разрешить доступ к вашему Диску. Если вам принципиально нельзя даже вставлять текст в редактор, этот необязательный шаг пока пропустите.

## Если что-то пошло не так

- **GitHub:** в репозитории должен быть **распакованный** код с сохранёнными папками, а не один ZIP.
- **Cloudflare Worker:** привязка называется `DB`, секрет называется `BRIDGE_TOKEN`; код из `cloudflare/src/index.js` вставлен **целиком**. Файлы `wrangler.jsonc` и `schema.sql` **не нужно** куда-либо вручную запускать или загружать в Cloudflare в этом способе.
- **Render:** четыре переменные из шага 4 должны быть заданы до первой публикации, пока база пуста. После переноса `INITIAL_IMPORT_TOKEN` удаляется. Секрет D1 должен совпадать с Worker.
- **Личные данные:** исходный ZIP остаётся у вас и не попадает в GitHub; Google-папка для копий тоже должна быть закрытой.

Справка по веб-панелям: [GitHub: загрузка перетаскиванием](https://docs.github.com/en/repositories/working-with-files/managing-files/adding-a-file-to-a-repository), [Cloudflare: D1 binding](https://developers.cloudflare.com/d1/get-started/), [Cloudflare: секреты](https://developers.cloudflare.com/workers/configuration/secrets/), [Cloudflare: Cron](https://developers.cloudflare.com/workers/configuration/cron-triggers/), [Render Free](https://render.com/docs/free).
