# Forma — учёт работы команды

Веб-приложение на русском языке, сделанное на основе предоставленного Excel-файла `source.xlsx`.

## Что уже работает

- 10 сотрудников и 23 вида работ импортированы из исходной таблицы; 2202 ежедневные записи перенесены за даты до 6 октября 2026 года включительно. Колонки с итогами за месяц и будущие даты не импортировались, чтобы не задваивать результат.
- Личные кабинеты сотрудников; вход по логину и паролю, роли «сотрудник» и «администратор». Сотрудник меняет только собственные количества и комментарии в «Мои работы», а также может писать сообщения в новом чате; табель и остальные доступные ему разделы — только для просмотра, изменение табеля, часов, учётных записей и паролей — только администратору.
- «Мои работы» — персональный лист в формате исходного Excel: работы по строкам, даты выбранного месяца по столбцам, единицы измерения и итог за месяц. Таблица раскрыта полностью по вертикали: отдельной вертикальной прокрутки внутри неё нет, длинную страницу листают обычным способом. Прокрутка по горизонтали для дат сохранена. Количество вводится прямо в ячейке и сохраняется при выходе из неё; допускается десятичная запятая. Очистка количества не стирает комментарий. Комментарий можно оставить даже без количества. Администратор выбирает над таблицей только пользователей с ролью «сотрудник»; обладатели прав администратора в этом списке не показываются. Обычный пользователь видит только свой лист.
- «Чат» для всех активных пользователей — личные переписки один на один и общий чат команды. Текстовые сообщения до 2000 символов сохраняются в Cloudflare D1 (локально — в SQLite); в интерфейсе личные сообщения видны только двум участникам, общие — всем вошедшим пользователям; это не сквозное шифрование, владелец базы/резервной копии имеет технический доступ к текстам. Пока чат открыт, новые сообщения подгружаются примерно каждые 3,5 секунды. Вложения и push-уведомления вне открытой страницы пока не поддерживаются. Сообщения входят в ручные и автоматические резервные копии; старые ZIP до появления чата по-прежнему можно восстановить, но переписки в них нет. Длинная история увеличивает размер базы: у существующего механизма атомарного восстановления D1 есть предел примерно 490 КБ на пакет.
- Общий каталог работ. Администратор добавляет работы, редактирует нормы/единицы измерения и архивирует виды работ; новые работы доступны всем действующим сотрудникам.
- Сводный отчёт по месяцу: количество и нормативное время по каждому пользователю с ролью «сотрудник» и виду работ. Пользователи с ролью «администратор» не попадают в строки и итоги сводки и скачиваемого Excel, но их старые записи не удаляются. Внизу для каждого сотрудника показываются рабочие часы по табелю и производительность: как в исходном Excel, округлённые до целого нормо-часы выполненных работ ÷ рабочие часы за выбранный месяц × 100 %. Изменение часов и отсутствие пересчитывают процент; при 0 часах ставится «—». Первый лист скачиваемого `.xlsx` повторяет **вкладку «Отчёт» исходного `source.xlsx`**: слева «По количеству» по сотрудникам и общее, затем «Норма времени», справа «По времени» по тем же сотрудникам и итог; ниже — «Общее», «Производительность», отработанные часы и месячные блоки Май–Декабрь / «Всё». Значения рассчитываются из текущих записей и табеля сайта для выбранного месяца, личный исходный Excel в код не включён. Дополнительные листы «Табель 5-2», «Записи», «Комментарии» сохранены (включая комментарии к пустым ячейкам).
- Табель 5/2 на любой месяц: пн–пт — плановая зелёная отметка, выходные — серая, отсутствие с причиной — красная. Можно явно отметить выход на работу в выходной день или вернуть день к графику.
- Плановые человеко-часы: пн–чт — 8,25 ч, пятница — 7 ч, выходные — 0 ч. При отсутствии в табеле всегда 0 ч. Администратор меняет часы на отдельный день для всей команды или индивидуально для сотрудника; индивидуальная настройка имеет приоритет. Сброс возвращает норму графика. Сумма часов показывается в табеле и отчёте и выгружается в Excel.
- Панель администратора: сотрудники, каталог работ, сводный отчёт, журнал последних 150 действий.
- Приветствие в разделе «Обзор» показывает полное ФИО текущего пользователя из его карточки в «Сотрудниках» (или имя основной учётной записи администратора).
- Боковое меню на компьютере и телефоне скрыто по умолчанию. Кнопка ☰ в верхнем левом углу открывает его поверх страницы; выбор раздела, крестик, нажатие за пределами меню или Escape закрывают его. Страницы используют почти всю ширину окна вместо прежних широких пустых полей. Основной шрифт — системный, увеличен, с более контрастным текстом.
- Локально — SQLite; для публикации на Render — Cloudflare D1 через приватный Worker. Данные включают пользователей, работы, выполненные задачи, табель, сеансы и аудит. Пароли хранятся с PBKDF2-SHA256 и индивидуальной солью; сеансы — с хешированием токена.

## Оформление чата

Автор может **до отправки** выбрать цвет облачка, включить или выключить подсветку, изменить её цвет и украсить границу сообщения: в каждой из четырёх категорий есть по 20 вариантов — эффекты рамки, цветы, ветви, декоративные обрамления точного знака «УП МИНГАЗ». Цветы и ветви разработаны с помощью генерации изображений ИИ; оригинальный знак сохранён без перерисовки и получен с [официального сайта УП «МИНГАЗ»](https://mingas.by/). Оформление сообщения видят получатели, оно остаётся неизменным после отправки. **«Рамка чата»** изменяет вид общего окна переписки у всех участников беседы; участники могут сохранить новый стиль, последнее сохранение действует для всех. Темы и оформление сообщений входят в ZIP-копии, аватары по-прежнему не входят. Чтобы поставить обновление на действующий сайт, загрузите одновременно серверные файлы, три файла интерфейса и три новые картинки: [пошаговая инструкция](CHAT_DEPLOY.md).

## Новые сообщения и аватары

На открытом сайте появляются всплывающие уведомления о новых личных и общих сообщениях справа внизу; в беседах отображаются отдельные счётчики, свыше 99 — `99+`. Пункт «Чат» расположен сразу за «Обзор». Аватар устанавливается кликом по круглой кнопке справа вверху: файл (автоматически сжимается до 90 КБ) либо публичная HTTPS-ссылка. Он показывается в верхней панели и рядом с участниками чата. При замене старый аватар перезаписывается в текущей D1. В ZIP-копии аватары **не попадают**, при восстановлении исчезают и загружаются повторно; переписки и отметки прочтения в ZIP сохраняются. Открытая вкладка проверяет новые сообщения примерно раз в три секунды; при закрытом сайте системных push-уведомлений нет. Для установки на действующий сайт следуйте [пошаговому обновлению](CHAT_DEPLOY.md).

## Публикация без команд

Следуйте только [пошаговой инструкции для браузера](DEPLOY_SIMPLE.md): распаковать архив кода → перетащить его содержимое в GitHub → вставить один файл Worker в редактор Cloudflare → создать Render-сайт → перетащить **личную** ZIP-копию на страницу `/setup`. На своём компьютере ничего устанавливать и запускать не нужно. `requirements.txt` Render установит сам.

## Первый вход

Локальная исходная копия содержит демонстрационный вход `admin` / `admin`. **Не публикуйте сайт с этим паролем:** защищённая страница `/setup` требует задать новый пароль основному администратору при переносе в D1, до первого публичного входа. Первоначальные пароли сотрудников находятся в конфиденциальном `initial_credentials.txt` (его **нет** в архиве для GitHub); передайте их работникам лично. Для новых сотрудников задавайте пароль при добавлении.

## Примечания

- Импорт из Google-таблицы выполнен однократно, **автоматической синхронизации с Google нет**: дальнейший учёт идёт в активной базе сайта (SQLite локально или D1 при явном `DATABASE_BACKEND=d1`).
- Зелёный квадрат означает **плановый рабочий день** по графику 5/2, а не подтверждённое присутствие системой проходной. Праздничные дни не определяются автоматически.
- Суммировать штуки, метры и архивные номера как единую физическую единицу некорректно; для сравнения производительности используйте нормо-часы и показатели по отдельным видам работ.
- Для публикации используйте HTTPS (Render даёт адрес `https://…onrender.com`), приватный Worker и резервные копии вне Render. База сайта живёт в Cloudflare D1, а не на локальном диске бесплатного Render. Встроенный HTTP-сервер подходит для небольшой команды; перед крупной нагрузкой необходим отдельный план масштабирования.
- Разработчик может проверить приложение изолированным тестом `test_app.py` в рабочей среде; для публикации через браузер этот тест не нужен и в безопасный архив не включён.

### Прикол (только для администратора)
В разделе «Прикол» выберите сотрудника со статусом «Сейчас в сети» и отправьте один из пяти эффектов: 40 быстро летающих человечков (каждый отскакивает 10 раз и исчезает), голосовое сообщение, **рыжего кота-курьера** с коротким посланием, карточку **«Достижение разблокировано»** с конфетти или **мини-парад** вдоль нижнего края. У каждого эффекта есть «Тест у себя» без отправки. Новые эффекты сами исчезают за 7–9 секунд и не перекрывают ввод. Для «Приколов» сделано исключение из системного уменьшения движения: кот, конфетти и парад видны в Edge, даже когда в Windows отключены эффекты анимации; спокойные обычные элементы сайта по-прежнему учитывают системную настройку. Кот нарисован отдельным PNG с прозрачным фоном; четыре кадра в `web/courier-cat-walk.png` попеременно меняют положение лап, пока CSS-анимация переносит его через экран. Сайт получателя должен быть открыт; статус обновляется автоматически примерно раз в 3 секунды. Если браузер блокирует автоматический голос, текст остаётся доступен для чтения и ручного озвучивания. Отправку проверяет сервер по роли администратора и текущему присутствию сотрудника; тексты не попадают в журнал действий (фиксируется лишь факт отправки и получатель). Новые виды событий используют старую схему D1 и SQLite без пересоздания базы.

### Кто в сети
В верхней части кабинета показывается состояние подключения «В сети» / «Не в сети». Нажмите «В сети», чтобы увидеть список всех пользователей, у которых сейчас открыт сайт (включая администратора). Список основан на регулярных проверках браузера; без связи, после закрытия вкладки или без активности соединения пользователь пропадает из списка примерно через 15 секунд.

### Права администратора и резервные копии
В «Сотрудниках» администратор может менять имя и логин сотрудника, назначить ему права администратора (и снять их позже) и сбросить пароль. Смена логина сохраняет все работы, табель и права, но завершает сеансы работника: он входит под новым логином со старым паролем. Повышение добавляет права, не превращая сотрудника в основную нештатную учётную запись: его записи, табель и показатели остаются в базе и графиках. Пока у него роль администратора, он не показывается в сводном отчёте (включая Excel и итоги) и в выборе сотрудников раздела «Мои работы». При возврате роли «сотрудник» сохранённые записи снова входят в отчёт. При запуске приложения ошибочно скрытые прежними версиями повышенные сотрудники возвращаются в списки без удаления записей; основная учётная запись администратора остаётся отдельной. Повышенный администратор получает те же возможности по управлению сайтом; нельзя снять права с самого себя через эту форму. При понижении его сеансы завершаются.

В разделе «Резервные копии» администратор скачивает ZIP-копию SQLite-базы, сравнивает загруженный старый архив с текущими данными (количество по таблицам, диапазон дат работ, число сотрудников/администраторов, время создания копии) и подтверждает полную замену. Перед заменой автоматически создаётся страховочный ZIP в `backups/`; он доступен для скачивания после повторного входа. Сеансы и временные события не входят в архив; при восстановлении все пользователи выходят из системы. Архив содержит хеши паролей: храните его конфиденциально. Для постоянной работы на Render Free нельзя держать ни рабочую SQLite, ни единственный бэкап только на его локальном диске.

Если сотрудник исчез из графиков после повышения до администратора, используйте [проверку версии и обновление действующего сайта](FIX_ADMIN_DEPLOY.md). В новой сборке `/health` показывает `"build":"20261007-34"`: если строки нет, Render продолжает отдавать старый код. Для установки текущей версии чата, оформления сообщений, уведомлений, счётчиков и аватаров: [пошаговая инструкция через браузер](CHAT_DEPLOY.md). Актуальная **инструкция без терминала**: [DEPLOY_SIMPLE.md](DEPLOY_SIMPLE.md). Код сайта перетаскивается в GitHub, Worker вставляется в редактор Cloudflare, личный ZIP-бэкап перетаскивается на защищённую страницу `/setup` (одноразовый `INITIAL_IMPORT_TOKEN`). Установку Wrangler, SQL-команды и перенос через командную строку выполнять не нужно. Первичный импорт сразу задаёт новый пароль главному администратору. Дополнительно: [почасовая проверка и ZIP-копии на Google Диске при изменениях](GOOGLE_DRIVE_BACKUP.md) с 08 до 17 по Минску включительно; Apps Script — `google_drive_backup.gs`, доступ к `/internal/backup` только через отдельный секрет Render `AUTOMATED_BACKUP_TOKEN`. Вход/выход и события «в сети» не считаются изменением рабочих данных. Google-аккаунт ещё не подключён. D1 работает только при явном `DATABASE_BACKEND=d1` вместе с `D1_WORKER_URL` и `D1_API_KEY`; без ключа перехода на SQLite нет. На Render локальная SQLite запрещена: пока D1 пуста, сайт открывает только защищённую одноразовую загрузку с `INITIAL_IMPORT_TOKEN`. Без него пустой сайт не запустится. Личный ZIP нельзя добавлять в GitHub. `/health` отвечает без подключения к базе; это проверка жизни процесса, не работоспособности D1. Периодический запрос Worker к `/health` — попытка уменьшить засыпание Render Free без гарантий доступности. При превышении около 490 КБ несжатого пакета транзакционное восстановление/миграция этим способом прекращается без замены данных; планируйте отдельный механизм для большой базы.
