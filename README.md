# Forma — учёт работы команды

Веб-приложение на русском языке, сделанное на основе предоставленного Excel-файла `source.xlsx`.

## Что уже работает

- 10 сотрудников и 23 вида работ импортированы из исходной таблицы; 2202 ежедневные записи перенесены за даты до 6 октября 2026 года включительно. Колонки с итогами за месяц и будущие даты не импортировались, чтобы не задваивать результат.
- Личные кабинеты сотрудников; вход по логину и паролю, роли «сотрудник» и «администратор». Сотрудник меняет только собственные количества и комментарии в «Мои работы»; табель и остальные доступные ему разделы — только для просмотра, изменение табеля, часов, учётных записей и паролей — только администратору.
- «Мои работы» — персональный лист в формате исходного Excel: работы по строкам, даты выбранного месяца по столбцам, единицы измерения и итог за месяц. Количество вводится прямо в ячейке и сохраняется при выходе из неё; допускается десятичная запятая. Очистка количества не стирает комментарий. Комментарий можно оставить даже без количества. Администратор выбирает сотрудника над таблицей, обычный пользователь видит только свой лист.
- Общий каталог работ. Администратор добавляет работы, редактирует нормы/единицы измерения и архивирует виды работ; новые работы доступны всем действующим сотрудникам.
- Сводный отчёт по месяцу: количество и нормативное время по каждому сотруднику и виду работ. Внизу для каждого сотрудника показываются рабочие часы по табелю и производительность: как в исходном Excel, округлённые до целого нормо-часы выполненных работ ÷ рабочие часы за выбранный месяц × 100 %. Изменение часов и отсутствие пересчитывают процент; при 0 часах ставится «—». В выгруженном `.xlsx` есть раздел производительности и листы «Табель 5-2», «Записи», «Комментарии» (включая комментарии к пустым ячейкам).
- Табель 5/2 на любой месяц: пн–пт — плановая зелёная отметка, выходные — серая, отсутствие с причиной — красная. Можно явно отметить выход на работу в выходной день или вернуть день к графику.
- Плановые человеко-часы: пн–чт — 8,25 ч, пятница — 7 ч, выходные — 0 ч. При отсутствии в табеле всегда 0 ч. Администратор меняет часы на отдельный день для всей команды или индивидуально для сотрудника; индивидуальная настройка имеет приоритет. Сброс возвращает норму графика. Сумма часов показывается в табеле и отчёте и выгружается в Excel.
- Панель администратора: сотрудники, каталог работ, сводный отчёт, журнал последних 150 действий.
- Боковое меню на компьютере и телефоне скрыто по умолчанию. Кнопка ☰ в верхнем левом углу открывает его поверх страницы; выбор раздела, крестик, нажатие за пределами меню или Escape закрывают его. Страницы используют почти всю ширину окна вместо прежних широких пустых полей. Основной шрифт — системный, увеличен, с более контрастным текстом.
- Локально — SQLite; для публикации на Render — Cloudflare D1 через приватный Worker. Данные включают пользователей, работы, выполненные задачи, табель, сеансы и аудит. Пароли хранятся с PBKDF2-SHA256 и индивидуальной солью; сеансы — с хешированием токена.

## Публикация без команд

Следуйте только [пошаговой инструкции для браузера](DEPLOY_SIMPLE.md): распаковать архив кода → перетащить его содержимое в GitHub → вставить один файл Worker в редактор Cloudflare → создать Render-сайт → перетащить **личную** ZIP-копию на страницу `/setup`. На своём компьютере ничего устанавливать и запускать не нужно. `requirements.txt` Render установит сам.

## Первый вход

Локальная исходная копия содержит демонстрационный вход `admin` / `admin`. **Не публикуйте сайт с этим паролем:** защищённая страница `/setup` требует задать новый пароль основному администратору при переносе в D1, до первого публичного входа. Первоначальные пароли сотрудников находятся в конфиденциальном `initial_credentials.txt` (его **нет** в архиве для GitHub); передайте их работникам лично. Для новых сотрудников задавайте пароль при добавлении.

## Примечания

- Импорт из Google-таблицы выполнен однократно, **автоматической синхронизации с Google нет**: дальнейший учёт идёт в активной базе сайта (SQLite локально или D1 при явном `DATABASE_BACKEND=d1`).
- Зелёный квадрат означает **плановый рабочий день** по графику 5/2, а не подтверждённое присутствие системой проходной. Праздничные дни не определяются автоматически.
- Суммировать штуки, метры и архивные номера как единую физическую единицу некорректно; для сравнения производительности используйте нормо-часы и показатели по отдельным видам работ.
- Для публикации используйте HTTPS (Render даёт адрес `https://…onrender.com`), приватный Worker и резервные копии вне Render. База сайта живёт в Cloudflare D1, а не на локальном диске бесплатного Render. Встроенный HTTP-сервер подходит для небольшой команды; перед крупной нагрузкой необходим отдельный план масштабирования.
- Разработчик может проверить приложение изолированным тестом `test_app.py` в рабочей среде; для публикации через браузер этот тест не нужен и в безопасный архив не включён.

### Прикол (только для администратора)
В разделе «Прикол» выберите сотрудника со статусом «Сейчас в сети» и отправьте один из пяти эффектов: 40 быстро летающих человечков (каждый отскакивает 10 раз и исчезает), голосовое сообщение, **рыжего кота-курьера** с коротким посланием, карточку **«Достижение разблокировано»** с конфетти или **мини-парад** вдоль нижнего края. У каждого эффекта есть «Тест у себя» без отправки. Новые эффекты сами исчезают за 7–9 секунд, не перекрывают ввод и учитывают настройку «Уменьшить движение». Кот нарисован отдельным PNG с прозрачным фоном; четыре кадра в `web/courier-cat-walk.png` попеременно меняют положение лап, пока CSS-анимация переносит его через экран. Сайт получателя должен быть открыт; статус обновляется автоматически примерно раз в 3 секунды. Если браузер блокирует автоматический голос, текст остаётся доступен для чтения и ручного озвучивания. Отправку проверяет сервер по роли администратора и текущему присутствию сотрудника; тексты не попадают в журнал действий (фиксируется лишь факт отправки и получатель). Новые виды событий используют старую схему D1 и SQLite без пересоздания базы.

### Кто в сети
В верхней части кабинета показывается состояние подключения «В сети» / «Не в сети». Нажмите «В сети», чтобы увидеть список всех пользователей, у которых сейчас открыт сайт (включая администратора). Список основан на регулярных проверках браузера; без связи, после закрытия вкладки или без активности соединения пользователь пропадает из списка примерно через 15 секунд.

### Права администратора и резервные копии
В «Сотрудниках» администратор может менять имя и логин сотрудника, назначить ему права администратора (и снять их позже) и сбросить пароль. Смена логина сохраняет все работы, табель и права, но завершает сеансы работника: он входит под новым логином со старым паролем. Повышение не удаляет личные работы, табель и показатели из отчёта. Повышенный администратор получает те же возможности по управлению сайтом; нельзя снять права с самого себя через эту форму. При понижении его сеансы завершаются.

В разделе «Резервные копии» администратор скачивает ZIP-копию SQLite-базы, сравнивает загруженный старый архив с текущими данными (количество по таблицам, диапазон дат работ, число сотрудников/администраторов, время создания копии) и подтверждает полную замену. Перед заменой автоматически создаётся страховочный ZIP в `backups/`; он доступен для скачивания после повторного входа. Сеансы и временные события не входят в архив; при восстановлении все пользователи выходят из системы. Архив содержит хеши паролей: храните его конфиденциально. Для постоянной работы на Render Free нельзя держать ни рабочую SQLite, ни единственный бэкап только на его локальном диске.

Актуальная **инструкция без терминала**: [DEPLOY_SIMPLE.md](DEPLOY_SIMPLE.md). Код сайта перетаскивается в GitHub, Worker вставляется в редактор Cloudflare, личный ZIP-бэкап перетаскивается на защищённую страницу `/setup` (одноразовый `INITIAL_IMPORT_TOKEN`). Установку Wrangler, SQL-команды и перенос через командную строку выполнять не нужно. Первичный импорт сразу задаёт новый пароль главному администратору. Дополнительно: [почасовая проверка и ZIP-копии на Google Диске при изменениях](GOOGLE_DRIVE_BACKUP.md) с 08 до 17 по Минску включительно; Apps Script — `google_drive_backup.gs`, доступ к `/internal/backup` только через отдельный секрет Render `AUTOMATED_BACKUP_TOKEN`. Вход/выход и события «в сети» не считаются изменением рабочих данных. Google-аккаунт ещё не подключён. D1 работает только при явном `DATABASE_BACKEND=d1` вместе с `D1_WORKER_URL` и `D1_API_KEY`; без ключа перехода на SQLite нет. На Render локальная SQLite запрещена: пока D1 пуста, сайт открывает только защищённую одноразовую загрузку с `INITIAL_IMPORT_TOKEN`. Без него пустой сайт не запустится. Личный ZIP нельзя добавлять в GitHub. `/health` отвечает без подключения к базе; это проверка жизни процесса, не работоспособности D1. Периодический запрос Worker к `/health` — попытка уменьшить засыпание Render Free без гарантий доступности. При превышении около 490 КБ несжатого пакета транзакционное восстановление/миграция этим способом прекращается без замены данных; планируйте отдельный механизм для большой базы.
