# Forma: закрытые групповые беседы и видеозвонки

**Подробное подключение LiveKit Cloud и бесплатные лимиты:** [`LIVEKIT_SETUP.md`](LIVEKIT_SETUP.md).

Версия кода: `20261023-53`. Действующий сайт Render **не обновляется** автоматически при создании этого архива. Перед публикацией сохраните свежий административный ZIP рабочей базы. Не помещайте ZIP с данными, `worktrack.sqlite3`, `initial_credentials.txt` и исходные персональные XLSX в GitHub.

## Обновление

1. Передайте на GitHub **все файлы нового архива**, в особенности `app.py`, `backup_tools.py`, `d1_store.py`, `cloudflare/schema.sql`, `web/main.js`, `web/calls.js`, `web/livekit-client.umd.min.js`, `web/index.html` и `web/styles.css`. Сохраняйте существующие секреты только в настройках хостинга.
2. Новые таблицы создаются при запуске `app.init_db()` как в SQLite, так и в D1. Существующие строки пользователей и переписок не перезаписываются. `group_chats`, `group_members`, `group_messages` входят в ZIP и миграцию D1. `call_sessions`, `call_participants`, `call_signals` временные и из ZIP исключены. При восстановлении все активные звонки прекращаются; после восстановления участники входят снова.
3. Для основного режима LiveKit Cloud укажите на Render переменные `LIVEKIT_URL=wss://...`, `LIVEKIT_API_KEY` и `LIVEKIT_API_SECRET` из вашего проекта LiveKit Cloud. **Никогда** не размещайте секрет в JS, GitHub, HTML или чате. Перезапустите приложение. Сервер выпускает временные JWT только вошедшим и имеющим право на конкретный звонок; клиент получает URL и временный токен после добровольного присоединения.
4. Если все три переменные не настроены, **новые** звонки работают через прямой P2P WebRTC (STUN; **без TURN**) максимум на 4 подключения. LiveKit-режим рассчитан на 15 подключений. Если LiveKit настроен, но соединение не установилось, браузер предлагает **явный** переход на P2P, но только пока в сессии не подключились другие участники; сервер запрещает смену режима начавшегося собрания. При необходимости администратор также может отключить LiveKit-переменные и перезапустить сайт для новых звонков.
5. Проверьте `GET /health`: маркер сборки должен быть `20261023-53`. В админке диагностика развёртывания должна показать новые файлы и корректную схему. P2P-видео проверено в двух отдельных браузерах Chromium с тестовыми камерами; настоящий LiveKit Cloud без ваших ключей не проверялся. На HTTPS-сайте отдельно проверьте две реальные камеры и демонстрацию экрана.

## Пользование и ограничения

- Чат → **+ Закрытая беседа**. Создатель выбирает минимум трёх других активных работников, то есть минимум четыре человека всего. Только создатель может менять название и состав; сообщения, оформление беседы, приглашения и сигналы доступны только её текущим участникам. Администратор не получает обходного доступа к чужой закрытой беседе через чат/API (однако полномочия по резервному копированию БД включают содержимое групп в ZIP).
- В личной, общей или закрытой беседе кнопка **Видеозвонок** создаёт видимую допущенным участникам сессию. Всплывающее приглашение предлагает **Присоединиться** или **Скрыть**. Камера/микрофон запрашиваются только после нажатия на подключение. Если устройства недоступны, предлагается участие только для просмотра.
- В звонке можно выключить камеру и микрофон, сменить камеру и показать экран. Экран, окно или вкладку выбирает сам пользователь через стандартный диалог Edge/Chrome; сайт не выбирает приложение автоматически. Для доступа к камере/экрану нужен HTTPS (либо localhost). Запись и хранение медиа не реализованы.
- Явный выход последнего участника завершает сессию. При разрыве браузера участники удаляются при истечении heartbeat (~45 секунд), а оставленная пустая сессия закрывается при уборке (~120 секунд). При сбое соединения могут потребоваться повторное приглашение и подключение.
- P2P образует mesh: каждый участник отправляет несколько видеопотоков, а STUN без TURN не работает надёжно за некоторыми NAT/корпоративными сетями. Даже на 4 участниках производительность зависит от устройства/канала; P2P **не предназначен для 15 человек**. Для регулярных общих собраний используйте LiveKit Cloud.
- При исключении участника его сигнализация удаляется сразу; штатные P2P-клиенты закрывают соединение с ним после следующего heartbeat. Если удаляемый сейчас присутствует в LiveKit-звонке, сервер запрашивает `RoomService.RemoveParticipant` (на LiveKit Cloud это также отзывает действующий токен). Если LiveKit не подтвердил исключение, изменение состава отменяется. Токен ранее ушедшего пользователя, который **уже покинул** звонок и не числится в таблице участников, отдельно не отзывается: до истечения срока JWT он теоретически может переподключиться напрямую к SFU, не используя API Forma. Для строгой политики отзыва всех ранее выданных токенов потребуется вести реестр выдачи токенов и отзывать их при каждом изменении состава; не используйте эту версию, если это обязательное требование. Выданные токены истекают через 10 минут для новых подключений.

## Проверки разработчика

Следующие регрессионные тесты запускаются в локальной рабочей папке разработчика с **тестовой копией** базы и не входят в публичный ZIP, чтобы случайно не опубликовать частные тестовые данные/реквизиты: `python test_calls_groups.py`, `python test_app.py`, `python test_sotipb.py`, `python test_d1_bridge.py`, `node test_ui.js`, `node test_calls_ui.js`. HTTP/SQLite/D1 тесты проверяют права доступа, архивы, P2P-сигнализацию, ограничения и подпись токена. Добавлен `python test_media_browser.py`: он проверяет передачу видео P2P между двумя браузерами Chromium с подставными камерами, перетаскивание окна и полный экран (для него локально нужны Playwright и Chromium). Тесты **не заменяют** проверку LiveKit Cloud и реальной камеры на HTTPS.

Браузерный пакет `web/livekit-client.umd.min.js` — `livekit-client` версии 2.23.0, Apache-2.0; текст лицензии включён в `web/livekit-client-LICENSE.txt`.

### Если видеоплитка собеседника не появляется в предпросмотре

В сборке `20261022-48` исправлена гонка P2P-сигналов: ранее предложение WebRTC могло прийти до списка участников и терялось, после чего обе камеры оставались только локальными. В новой версии ранний сигнал сохраняется до появления участника, а его имя отображается сразу после входа. Если браузер встраивает сайт в iframe и блокирует камеру/микрофон, откройте **живой адрес предпросмотра в отдельной вкладке HTTPS**, подтвердите разрешения и перезайдите в звонок. В окне добавлены кнопка «На весь экран» (с увеличением внутри iframe, если браузер запрещает настоящий fullscreen) и перетаскивание за заголовок. P2P без TURN по-прежнему может не работать за определёнными NAT.
